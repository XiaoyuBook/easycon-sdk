# 0001：外层 SDK 与 EasyCon 源码分离

- 状态：Accepted
- 日期：2026-07-16

## 背景

工作目录包含两个不同的所有权边界：外层 `easycon sdk/` 是二次开发项目，内层 `EasyCon/` 是本地携带的第三方源码。两者需要能够一起用于开发和跨电脑迁移，但不能在外层 Git 仓库中混为同一份源码。

## 决策

1. SDK 自有代码、文档、测试和发布配置全部由外层仓库管理。
2. 外层 Git 完整忽略 `EasyCon/`，不将其作为 submodule，也不记录远程地址、分支或提交锁。
3. 外层仓库不提供自动下载、更新或修改 EasyCon 源码的脚本。
4. EasyCon 的内部实现类型不直接构成多语言 SDK 的公共接口。
5. 需要同时迁移两部分内容时，直接打包并复制完整的工作目录。

本决策只规定源码所有权和版本控制边界，不预先决定共享核心、ABI、语言绑定或进程模型。

## 结果

- 外层 SDK 可以拥有独立的版本、提交历史和发布流程。
- EasyCon 源码保留其原有许可证、版权和内部版本控制信息。
- 仅克隆外层仓库不会获得 `EasyCon/`，需要另外放回该目录或复制完整工作目录。
